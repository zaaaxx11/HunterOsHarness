## Key Risks

### Risk 1 — CRITICAL: Signature bypass → fund drain

- **F-0008** [evm-unverified-assumption] `RelayAllocator.consumeSpenderSignature`
  — spender signature validation return value ignored, allowing forged withdrawals.
- **F-0005** [reentrancy] `WithdrawGasPayer.payGas`
  — external call `HUB.burn(...)` occurs BEFORE the state write
  `gasPayments[withdrawParamsHash] = feeAmount`, enabling reentrant gas-fee dodging
  or double-withdrawal paths.

**Attack chain:** forge spender signature → trigger withdrawal → reenter via
`HUB.burn` callback → drain `RelayFundingPool` before `gasPayments` is written.

**Remediation:** Validate the return value of `consumeSpenderSignature` — revert on
failure. Reorder `payGas` to follow checks-effects-interactions: write
`gasPayments[...]` BEFORE calling HUB.

---

### Risk 2 — HIGH: Oracle signature bypass + amount manipulation

- **F-0006** [evm-unverified-assumption] `RelayOracleMultisig._validateSignatures`
  — return value ignored, meaning invalid multisig sigs may pass validation.
- **F-0001** [evm-arithmetic-trust] `RelayFundingPool._requireAmount`
  — strict equality `amount == 0` is bypassable via crafted input.

**Attack chain:** bypass oracle multisig check → inject crafted withdrawal /
funding amount that passes `_requireAmount` equality check → manipulate pool
accounting or trigger undercollateralized payouts.

**Remediation:** Add explicit `require(validateSignatures(...) == true)` pattern.
Replace strict-equality guards with bounded range checks.

---

### Risk 3 — MEDIUM: Dual reentrancy in price feed path

- **F-0003** [reentrancy] `StorkFastAdapter.decodeAndVerify`
  — external call `STORK_FAST_VERIFIER.verifyAndDeserialize(...)` before state write
  `cachedReportHash = reportHash`.
- **F-0004** [reentrancy] `RelayUsdRateLimiter.consume`
  — external call `PRICE_ORACLE.resolveUsdPrice(...)` before state update `usdValue`.

**Attack chain:** malicious price feed triggers reentrant `decodeAndVerify` /
`consume` → repeated rate updates within a single tx → USD rate limiter cap
bypass on funding-pool withdrawals.

**Remediation:** Apply CEI (checks-effects-interactions) — cache oracle call
results to local memory, write state first, then perform external calls.

---

## Remediation Priorities

1. Validate return value of `RelayAllocator.consumeSpenderSignature`
2. Reorder `WithdrawGasPayer.payGas` — CEI pattern (state write before external call)
3. Replace strict equality `== 0` with bounded range checks in `_requireAmount`, `_computeQueryId`
4. Validate all oracle return values (`_validateSignatures`, `_addSource`)
